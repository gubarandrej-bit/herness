# ⚡ herness

**Система анализа и проверки рабочей документации по инженерным системам.**

Проверка проектной и рабочей документации на соответствие нормативно-техническим документам РФ (ГОСТ, СП, ПУЭ, 123-ФЗ). Поддерживаемые системы: электроснабжение, электроосвещение, пожарная сигнализация, СОУЭ, пожаротушение, СКС/ЛВС/ВОЛС, видеонаблюдение, СКУД, охранная сигнализация, АСУ, АСУТП.

---

## 🚀 Быстрый старт (одна команда)

```bash
curl -fsSL https://raw.githubusercontent.com/gubarandrej-bit/herness/main/install.sh | bash
```

Или через wget:

```bash
wget -qO- https://raw.githubusercontent.com/gubarandrej-bit/herness/main/install.sh | bash
```

Скрипт автоматически:
1. Проверяет наличие Docker и Docker Compose
2. Клонирует репозиторий
3. Собирает и запускает приложение
4. Проверяет работоспособность
5. Предлагает установить локальную ИИ-модель (Ollama)

После установки открыть в браузере:

```
http://<ip-вашего-сервера>:8080

Логин:    admin
Пароль:   admin123
```

## 📋 Ручная установка

### Требования

- **Docker** 24+ и **Docker Compose** v2
- **Процессор:** x86_64, 4+ ядра (рекомендуется 8)
- **ОЗУ:** 2 ГБ минимум (без ИИ), 8+ ГБ (с локальной ИИ-моделью)
- **Диск:** 10 ГБ свободно (60 ГБ с учётом моделей ИИ)
- **ОС:** Linux (Ubuntu 22.04+, Debian 12+, CentOS 9+), macOS, Windows (WSL2)

### Установка

```bash
# 1. Клонировать репозиторий
git clone https://github.com/gubarandrej-bit/herness.git
cd herness

# 2. Запустить приложение
docker compose up -d --build

# 3. Проверить, что сервер запустился
curl http://127.0.0.1:8080/health

# 4. Открыть в браузере http://<ip-сервера>:8080
```

### Установка локальной ИИ-модели

```bash
# 1. Запустить контейнер Ollama
docker compose --profile local-ai up -d

# 2. Скачать модель (~4 ГБ)
docker compose exec ollama ollama pull qwen2.5:7b-instruct

# 3. В веб-интерфейсе выбрать: Настройки → Режим → local
```

## 🔧 Режимы работы

| Режим | Описание |
|---|---|
| **local** | Все запросы к ИИ через локальный Ollama. Без доступа в интернет. |
| **cloud** | Анализ через облачные модели. Требуется добавить модель в админ-панели (API-ключ). |
| **hybrid** | Сначала локальная модель. Если недоступна — облачная. |

Для добавления облачной модели: Админ-панель → «Модели ИИ» → «+ Добавить модель».
Поддерживаются любые OpenAI-совместимые API (Qwen, DeepSeek, GPT и др.).

## 🧪 Выполняемые проверки

1. **Кабельный журнал** — марки, сечения, длины, минимальные сечения по ПУЭ
2. **Спецификация оборудования** — перечень, количество, сверка с журналом
3. **Сверка кабельного журнала со спецификацией** — наименования и количество
4. **Источники питания** — расчёт тока, мощности, подбор аккумуляторов
5. **Выбор кабелей по нагрузкам** — сечения по ПУЭ, марки по пожарной безопасности (ГОСТ 31565)
6. **Планы трасс** — сверка длин с кабельным журналом (при наличии планов)
7. **Прилагаемые расчёты** — проверка наличия и состава

> Если для проверки не хватает данных — система сообщает об этом и пропускает шаг. Ничего не выдумывается.

## 📊 Отчёты

- **DOCX** — полный отчёт с замечаниями, ссылками на пункты НТД (разделение на критические/некритические)
- **XLSX** — табличный отчёт с листами: Проверки, Замечания, Файлы
- **Ведомость объёмов работ** и **ведомость оборудования и материалов**

## 🗄️ База нормативно-технических документов

При первом запуске система автоматически извлекает текст из PDF в `docs/ntd/` и заполняет базу.

**15 документов:**

| Код | Название |
|---|---|
| 123-ФЗ | Технический регламент о требованиях пожарной безопасности |
| ПУЭ | Правила устройства электроустановок (изд. 7) |
| СП 3.13130.2026 | Системы противопожарной защиты. СОУЭ |
| СП 6.13130.2025 | Электроустановки низковольтные. Требования ПБ |
| СП 76.13330.2016 | Электротехнические устройства |
| СП 484.1311500.2020 | Системы пожарной сигнализации |
| СП 486.1311500.2020 | Перечень зданий, подлежащих защите АУП |
| ГОСТ 21.208-2013 | Условные обозначения средств автоматизации |
| ГОСТ Р 21.101-2026 | Основные требования к проектной документации |
| ГОСТ 21.210-2014 | Условные графические изображения электрооборудования |
| ГОСТ Р 21.703-2020 | Правила выполнения документации проводных средств связи |
| ГОСТ 31565-2012 | Кабельные изделия. Требования ПБ |
| ГОСТ Р 53246-2025 | СКС. Проектирование узлов системы |
| ГОСТ Р 58238-2018 | Слаботочные системы. Кабельные системы |
| СП 48.13330.2019 | Организация строительства |

Проверка актуальности: веб-интерфейс → «База НТД» → «Обновить статус».

## 🛠️ Команды управления

```bash
# Просмотр логов
docker compose logs -f app

# Остановка
docker compose down

# Полная перезагрузка (с пересборкой)
docker compose up -d --build

# Обновление версии
git pull origin main
docker compose up -d --build

# Очистка данных (удалит БД и загруженные документы)
docker compose down -v
```

## ⚙️ Системные требования к серверу

| Параметр | Минимальные | Рекомендуемые |
|---|---|---|
| CPU | 4 ядра | 8+ ядер |
| RAM | 2 ГБ | 8+ ГБ |
| SSD | 10 ГБ | 60 ГБ |
| Docker | 24+ | последняя |
| GPU (для ИИ) | не требуется | NVIDIA RTX 8+ ГБ (опционально) |

> **Примечание:** Процессор AMD FX-8120 (2011 г.) не поддерживает AVX2-инструкции,
> необходимые для современных сборок llama.cpp/Ollama. На таком процессоре локальная
> ИИ-модель будет работать крайне медленно. Рекомендуется использовать процессор с
> поддержкой AVX2 (Intel Haswell 2013+ / AMD Ryzen).
