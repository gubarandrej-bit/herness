# ⚡ herness

**Система анализа и проверки рабочей документации по инженерным системам.**

Проверка проектной и рабочей документации на соответствие нормативно-техническим документам РФ (ГОСТ, СП, ПУЭ). Поддерживаемые системы: электроснабжение, электроосвещение, пожарная сигнализация, СОУЭ, пожаротушение, СКС/ЛВС/ВОЛС, видеонаблюдение, СКУД, охранная сигнализация, АСУ, АСУТП.

---

## 🚀 Быстрый старт

### Требования к серверу

- Docker Engine 24+ и Docker Compose v2
- 2+ ГБ свободной оперативной памяти (для локальной ИИ-модели потребуется 8+ ГБ)
- Свободное место: 60 ГБ SSD (включая систему, БД, загруженные документы и отчёты)

### Установка

```bash
# 1. Клонировать репозиторий
git clone https://github.com/gubarandrej-bit/herness.git
cd herness

# 2. Положить файлы НТД (ГОСТ, СП, ПУЭ) в папку docs/ntd
#    Уже приложены 13 документов. При необходимости добавьте недостающие:
#    - 123-ФЗ "Технический регламент о требованиях пожарной безопасности"
#    - ПУЭ "Правила устройства электроустановсов" изд. 7

# 3. Запустить приложение
docker compose up -d --build

# 4. Открыть в браузере
#    http://<ip-сервера>:8080
#
#    Логин:    admin
#    Пароль:   admin123
```

### Локальная ИИ-модель (опционально)

```bash
# 1. Запустить с Ollama
docker compose --profile local-ai up -d --build

# 2. Загрузить модель (первый запуск)
docker compose exec ollama ollama pull qwen2.5:7b-instruct

# 3. В настройках приложения выбрать режим "local" и модель qwen2.5:7b-instruct
```

## 🔧 Режимы работы

| Режим | Описание |
|---|---|
| **local** | Все запросы к ИИ выполняются через локальный Ollama. Без интернета. |
| **cloud** | Анализ через облачные модели, добавленные администратором. |
| **hybrid** | Сначала локальная модель. Если она не отвечает — облачная. |

**Добавление/удаление облачных моделей:** Админ-панель → «Модели ИИ» → «+ Добавить модель». Укажите name, kind=cloud, provider, base_url, model_id, api_key.

## 📋 Входные форматы

| Формат | Расширение | Статус |
|---|---|---|
| Microsoft Excel | .xls, .xlsx, .xlsm | ✅ Полная поддержка |
| Microsoft Word | .doc, .docx | ✅ Полная поддержка (через python-docx + LibreOffice) |
| PDF | .pdf | ✅ Извлечение текста |
| AutoCAD | .dwg, .dxf | ⚠️ DWG требует ODA File Converter (установить отдельно). DXF поддерживается в режиме заглушки |

## 🧪 Проверки документации

Система выполняет следующие проверки (при наличии исходных данных):

1. **Кабельный журнал** — марки, сечения, длины, соответствие ПУЭ
2. **Спецификация оборудования** — перечень и количество
3. **Сверка кабельного журнала со спецификацией** — наименования и количество
4. **Источники питания** — расчёт тока и мощности, подбор аккумуляторов
5. **Выбор кабелей по нагрузкам** — проверка сечений по ПУЭ, марки по пожарной безопасности
6. **Планы трасс** — сверка длин с кабельным журналом (при наличии планов)
7. **Прилагаемые расчёты** — проверка наличия и состава

> Если для проверки не хватает данных — система сообщает об этом и пропускает проверку. Ничего не выдумывается.

## 📊 Отчёты

- DOCX — полный отчёт с замечаниями, ссылками на НТД, разделением на критические/некритические
- XLSX — табличный отчёт с листами: Проверки, Замечания, Файлы
- Встроенная ведомость объёмов работ и материалов

## 🗄️ База НТД

При первом запуске система сканирует `docs/ntd` и заполняет базу нормативно-технических документов:

- СП 3.13130.2026, СП 6.13130.2025, СП 76.13330.2016
- СП 484.1311500.2020, СП 486.1311500.2020
- ГОСТ 21.208-2013, ГОСТ Р 21.101-2026, ГОСТ 21.210-2014
- ГОСТ Р 21.703-2020, ГОСТ 31565-2012, ГОСТ Р 53246-2025
- ГОСТ Р 58238-2018, СП 48.13330.2019, ПУЭ

Для проверки актуальности откройте «База НТД» → «Обновить статус».

## 🛠️ Администрирование

## 📝 Примечания

- Размер загружаемых файлов — до 200 МБ
- Сессии пользователей живут 12 часов
- База данных — SQLite, хранится в томе `herness-data`
- DWG поддерживается только через внешний ODA File Converter (см. документацию)
